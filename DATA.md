# Data

This repository holds code, results and logs. It does not redistribute third-party data or query corpora; each folder's `README.md` has the exact steps. Check each source's own terms before use.

| Data | Used for | Where to get it | Script |
|---|---|---|---|
| Hockey, VOC, NCVoter, UniProt, HPI and UCI benchmark tables | Mining, decisions, timings | The authors' copies of the public benchmarks; `discovery/run_csv.py` and `discovery/datasets2.py` list the files | `discovery/` |
| LakeBench open-data tables | Decisions on open data | github.com/BIT-DataLab/LakeBench; the sampled tables are listed in `discovery/lakebench_tables.json` | `discovery/lakebench/` |
| Application schemas (GitLab, Mastodon, Forem, Chatwoot, Loomio, Consul, Open Food Network, Maybe, DocuSeal, Campsite) | Table I and application code | The projects' public repositories | `schemas_study.py`, `apps/` |
| SchemaPile | Predicate shapes | The SchemaPile dataset | `schemapile/sp_count.py` |
| dbt projects | Scoped uniqueness tests | Public repositories named in `dbt/README.md` | `dbt/dbt_scopes.py` |
| Stack Exchange data and the SEDE corpus | Workload and recommendations | Stack Exchange data dump; the SEDE repository | `stackexchange/` |
| Discourse queries | Workload | Discourse Data Explorer and meta.discourse.org | `discourse/collect.py` |
| MusicBrainz, ListenBrainz, MetaBrainz forum | Workload | MusicBrainz data dumps; public repositories; community.metabrainz.org | `musicbrainz/` |
| SkyServer query log and schema | Workload | SkyServer's public SQL search service | `sdss/sdss_log.py`, `sdss/sdss_schema.py` |
| Wikimedia Quarry queries, wiki dumps | Workload | Hugging Face `htriedman/wikidb`; dumps.wikimedia.org | `quarry/` |
| TPC-DS, STATS-CEB | Benchmarks | DuckDB's `tpcds` extension; the STATS-CEB repository | `experiments/tpcds/load_tpcds.py`, `stackexchange/se_statsceb.py` |

## Left out on purpose

- **Per-query dumps of user-written SQL:** Quarry, SkyServer, SEDE, Discourse and the MetaBrainz forum. They are other people's text under their own terms, and the Quarry queries contain IP addresses of wiki editors. The summaries are in the `log_*` files, and the scripts regenerate the dumps from the sources.
- **SkyServer client addresses:** never collected; `sdss_log.py` fetches only the statement, its database and the number of runs.
- **`discovery/results/hockey-Teams-Coaches.json`:** 163 MB; `discovery/run.py` regenerates it.
- **Superseded runs:** results of earlier builds (`*_before_*`, `*_semibug*`, `*_prejoins*`).

`experiments/sql_unique/x4_decisions_lb.json.gz` is compressed; use `gunzip` to read it.

`apps/sites_*.json` and `apps/x5_*.json` hold short SQL statements taken from the applications' public code, some of them under AGPL, kept because they cannot be regenerated by a script.
